## 目标与范围

集中编写并执行全部新增测试，验证关键正确性、完整调查流程和受影响的 Tau 功能；修复缺陷并复测后形成交付结论。本阶段覆盖固定模型、少量代表场景，不安排 benchmark、多模型比较或消融实验。

## 模块与测试入口

- 新增 `tests/incident/`，按存储提交、上下文执行、调度恢复、审查记忆、遥测分析、接入交互组织测试文件；共享辅助放在该目录的 `conftest.py`，避免污染已有测试。
- 复用 `tau_ai.fake.FakeProvider`，在本阶段添加脚本化事件、fake 时钟、遥测、容器驱动和观测导出器。使用临时 SQLite/artifact 目录和可控并发屏障，验证实际状态及副作用。
- 补充已有 `tests/test_agent_loop.py`、`test_agent_harness.py`、`test_tool_history.py` 等受影响文件。真实模型和容器用例显式区分依赖条件，默认离线检查不能冒充这些用例已通过。
- 复用 Stage 5 的环境、导出工具和 FixtureProvider；标准答案与评估断言仅存在于 Agent 不可访问的测试/场景控制端。

## 执行步骤

1. **冻结验证输入。** 记录实现提交、依赖锁文件、Demo/镜像/场景版本、操作系统、模型配置和预算。核对前六阶段交付物与矩阵，无未实现占位后开始行为验证；部署参数在此落实，缺少条件的项目标为待验证。
2. **编写确定性测试。** 按 V1–V9 补齐正常、冲突、取消、超时、中断和失败路径。存储使用真实临时 SQLite，关键时序使用可控屏障与 fake 时钟，覆盖事务提交前后、请求快照前后及执行返回前后的中断。断言领域结果和可追溯记录，不仅比较函数调用次数。
3. **执行并修复核心行为。** 通过 `uv run pytest tests/incident` 按组运行离线用例，记录失败条件和关联请求/事件。修复回到所属模块，补充能复现缺陷的测试，再复测失败用例与受影响组；涉及共享协议、事务或生命周期时扩大到对应 Tau 回归。
4. **执行受影响的原有回归。** 覆盖 agent loop/harness/tool history、Pi event protocol、跨 provider 历史、coding/session/session manager、commands/CLI/RPC/TUI、context window、provider runtime、project trust、extensions、paths 和 package metadata 的现有测试。随后运行 `uv run pytest` 核对整套 Python 测试；外部环境用例必须另外明确执行结果。
5. **运行少量完整场景。** 先用确定性 provider 和查询数据完成整条流程，再在 WSL2 启动锁定的 Demo、分析镜像和观测后端，使用一个固定模型执行下列场景。实际导出数据并通过 FixtureProvider 查询回放，核对覆盖与来源；不要求模型生成轨迹逐字相同。
   - checkout/payment 调用异常：人工开案与配置的告警入口均能启动调查，取得相关证据、审查结论并生成报告；真实配置变更与故障开关的来源分别核对。
   - 晚到证据和进程中断：并行调查中暂停/退出后继续，修订受影响判断，业务恢复后仍正确处理未完成诊断。
   - 相似历史案例：新案件引用旧卡片后根据反证修正，触发局部修复和版本更新；验证历史来源失效能够阻止继续使用过期卡片。
6. **验收产品与部署边界。** 实际检查 CLI、案件 TUI、RPC、后台断连重连、Webhook 重复与乱序、报告/交接、时间线和 Jaeger 关联。执行容器隔离与取消用例、导出后端不可用及本地存储错误用例。Windows 应用路径/导入和 WSL2 容器路径均覆盖，旧 coding 模式可继续使用。
7. **完成复测与记录。** 对最终代码执行必要的 Ruff、mypy、打包和文档检查；命令沿用仓库配置，Python 经 `uv`。记录测试命令、结果、缺陷修复提交、复测范围、环境与仍有限制，更新指南和参考中的验证说明。
